# 植物大战僵尸 (Plants vs Zombies) — 前端复刻项目规划

> 技术选型：**原生 JavaScript + Canvas 2D**，美术采用 **Canvas 程序化绘制（矢量图形）**
> 本文件为总体规划，后续按章节拆分为迭代任务逐一实现。

---

## 1. 项目概述

- **目标**：用纯前端技术实现一款可玩、可扩展的塔防游戏《植物大战僵尸》核心玩法。
- **运行方式**：静态网页，`index.html` 直接打开或通过任意静态服务器运行，无第三方依赖、无构建步骤。
- **平台**：桌面浏览器（键盘 + 鼠标操作），预留移动端触控适配扩展点。
- **兼容性**：优先支持 Chrome / Edge / Firefox 最新版。

---

## 2. 技术栈与核心思路

| 项 | 选择 | 说明 |
|---|---|---|
| 语言 | 原生 JavaScript (ES6+) | 模块化：单个 `<script>` 内分文件管理 |
| 渲染 | Canvas 2D API | 主游戏画面统一 Canvas 绘制，按需分层 |
| 界面 | HTML + CSS | 菜单、选卡、状态栏等 UI 用 DOM，游戏画面用 Canvas |
| 美术 | 程序化绘制 | 用绘制函数（圆、矩形、曲线）画植物/僵尸/子弹，可切换配色与参数 |
| 音效 | Web Audio API | 用振荡器程序化合成音效，无音频文件 |
| 存档 | localStorage | 记录关卡进度、解锁状态、最高记录 |

### 架构分层

```
UI 层 (DOM)      —— 菜单、关卡选择、卡片栏、信息面板
游戏层 (Canvas)  —— 场景、网格、实体渲染、特效、粒子
逻辑层 (JS)      —— 游戏循环、实体系统、碰撞、规则
数据层 (JS)      —— 静态配置（植物/僵尸/关卡数值）、存档
```

## 4. 核心玩法设计

### 4.1 基本规则
- 战场为 **5 行 × 9 列** 网格，僵尸从右侧出现向左行进。
- 玩家消耗 **阳光** 在网格上种植植物，植物攻击/阻挡僵尸。
- 僵尸到达 **左侧草坪终点（啃食植物或家）** 即游戏失败；守住全部波次即胜利。

### 4.2 游戏流程
```
主菜单 → 关卡选择 → 开始游戏(选卡阶段) → 准备(倒计时) → 战斗(波次) → 胜利/失败结算 → 返回菜单
```

### 4.3 选卡阶段
- 弹出植物卡片列表，玩家从已解锁卡片中选择（默认限制数量，如 6~10 张）。
- 战斗中卡片栏有 **阳光消耗** 与 **冷却时间** 两种状态。

## 5. 实体系统设计

### 5.1 植物（初始版：6 种）

| 植物 | 阳光 | 冷却 | 生命 | 行为 |
|---|---|---|---|---|
| 向日葵 | 50 | 7s | 300 | 每隔 ~10s 产出一个阳光（50 阳光） |
| 豌豆射手 | 100 | 7s | 300 | 每 1.4s 发射一颗豌豆，直线飞行，20 伤害 |
| 坚果墙 | 50 | 30s | 4000 | 无攻击，高生命阻挡僵尸 |
| 樱桃炸弹 | 150 | 50s | 高 | 种植后短延迟爆炸，3×3 范围 1800 伤害 |
| 寒冰射手 | 175 | 7s | 300 | 同豌豆，额外减速僵尸 4s（移速 ×0.5） |
| 双发射手 | 200 | 7s | 300 | 一次发射 2 颗豌豆 |

> 数值集中在 `config.js` 的植物配置表中，后续扩展新植物只需追加配置 + 绘制函数。

### 5.2 僵尸（初始版：3 种）

| 僵尸 | 生命 | 移速(格/s) | 攻击 | 特点 |
|---|---|---|---|---|
| 普通僵尸 | 200 | 1/4 | 20/0.5s 啃食 | 基础单位 |
| 路障僵尸 | 400 | 1/4 | 20/0.5s | 生命更高 |
| 铁桶僵尸 | 700 | 1/4 | 20/0.5s | 生命很高 |

- 僵尸状态机：`行走 → 攻击(啃植物) → 死亡(倒地淡出) → 到达终点(失败)`
- 波次刷怪：每关由 `config.js` 中关卡配置驱动（按时间点 / 波次生成僵尸）。

### 5.3 子弹系统
- 豌豆类子弹沿行直线飞行，命中第一个僵尸后消失并结算伤害。
- 寒冰子弹附加减速状态（僵尸身上的 status 状态条）。

### 5.4 阳光系统
- 来源：向日葵产出 + 天空随机掉落（概率性，暖色阳光 +25）。
- 点击阳光实体（或拖拽收集）→ 加计数，弹出飘字效果。

## 6. 渲染与美术方案（Canvas 程序化绘制）

- 统一 `draw.js` 提供绘制函数：`drawSunflower() / drawPeashooter() / drawWallnut() / drawZombie() ...`
- 每个实体在 `update(dt)` 中记录动画时间 `t`，绘制时用 `t` 驱动轻微摆动/呼吸动画。
- 绘制分层顺序：**草坪背景 → 网格 → 阳光/植物/僵尸 → 子弹 → 特效 → 顶栏 UI**。
- 颜色与大小集中定义常量，便于整体换肤。

## 8. 音效与反馈（Web Audio）

- 程序化合成：种植音效、豌豆发射、僵尸啃食、爆炸、阳光收集、胜负音乐（简单旋律循环）。
- 视觉反馈：命中闪光、受击抖动、死亡淡出、阳光飘字、按钮悬停效果。

---

## 9. 关卡设计

- 每关配置：`{ 网格可用行、初始阳光、植物池、波次表 [{time, type, count}] }`
- 示例：关卡 1-1 只出普通僵尸少量波次，作为教学；后续关卡逐步解锁新植物与强僵尸。
- 难度曲线：僵尸数量/密度/类型随关卡编号提升。

## 12. 风险与注意点

- **性能**：实体数量大时注意对象复用（对象池），减少每帧绘图状态切换。
- **数值平衡**：所有数值收敛到 `config.js`，方便统一调整与测试。
- **可扩展性**：新植物/僵尸 = 配置表 + `draw.js` 绘制函数 + 可选专属逻辑，三者低耦合。
