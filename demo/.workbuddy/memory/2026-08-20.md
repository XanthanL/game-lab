## M3-K 顶层同色合并 + 像素管线接通 + 可旋转立体棋盘（用户五点需求）
用户需求：① 仅顶层同色相邻才合并；② 全面像素风（字体/界面/图形）；③ 六边形缝隙小一点；④ 立体效果 + 拖动旋转棋盘看被挡格；⑤ 优化代码。

- **① 顶层规则（board.ts）**：`colorComponent` 的成员判定从 `stack.some(color)` 改为 `topColor(idx) === color`（新增 `topColor()`）；`allBoardColors`/`firstCellWith` 同步改顶层语义。`startConsolidate` 重写为**整摞迁移**：非锚格全部 tile（底→顶）登记飞行（layer 连续累加），`src.stack = []`，埋藏异色随行且顺序保持；锚格合并后顶层仍是触发色（链式结算正确）。消除从"连通块计数"改为 `pickClearIdx()` 单格扫描（Map 计数每色，≥10 即 `clearCellColor(idx, color)` 消除该色全部）——合并先行会把同顶层色收进一格，故单格判定等价且更简洁；埋藏满 10 在收拢/消除后同样触发（测试 27b 验证 10红+顶蓝 的连锁）。
- **② 像素管线（game.ts，重大）**：发现 `game.ts` 的离屏 buffer 从 M1 起**从未被使用**（`board.render(ctx)` 直绘主画布，注释吹的像素管线是死代码）。接通：`bctx.setTransform(1/PIXEL)` → `board.render(bctx)` → `ctx.drawImage(buffer, NN 放大)`；`PIXEL=2`（3 会让中文糊成 6.7px 不可读）。字体全面换等宽栈 `pxFont()`（Courier New/Consolas/monospace）；按钮/托盘/Toast 改方角像素斜面（`shade()` 亮/暗双色 + fillRect）；`drawCellStack` 计数字体等宽。浏览器像素级验证：扫描线 60 处颜色突变 **100% 落在偶数 x**（2x 像素块铁证），~61fps。
- **③ 缝隙**：`CELL_R_RATIO` 0.9→0.95（缝隙 0.173s→0.087s，减半）；布局 maxW 0.99→0.95 / maxH 0.56→0.66（按 TILT 补偿 + 旋转余量）。
- **④ 立体视角（board.ts）**：`viewAngle` + `TILT=0.8`；`boardToScreen/screenToBoard` 严格互逆（渲染变换 `translate→scale(1,TILT)→rotate→translate` 与数学换算同源——注意 canvas 是 scale 在 rotate 外层=屏幕系压缩，写反会旋转轴错乱）；`pointerUp` 命中改在棋盘平面坐标找最近格（旋转/俯角不影响准确度）；渲染按 `boardToScreen(c).y` 升序排序（远→近，前方棋堆遮挡后方，转视角可见被挡格）；托盘/HUD/弹窗在屏幕层不转；`pointerDown` 空白处（非按钮/非组）→ `rotating` 手势（`ROT_SENS=0.008 rad/px`），合并动画期间也允许旋转；`game.ts` 输入改为全转发（原先 dragId 门控会吞掉旋转的 move/up）。浏览器实测：150px 拖动 = +1.200rad 精确、反向拖回精确归零、白格翻转率 15.7% 确认旋转。
