# Content Profile — 画像与约束判定

## 画像

- B0 源：口述需求 + 参考站 URL + 设定型实体信息（用户答复）
- B1 受众：路过/潜在客 + 回头客（公开，查活动）
- B2 目标：到店 + 查活动；MVP = 单页 + 活动台账 + 到店信息
- B3 资产：文字量级小；图片 0 张；无 VI/无 logo（只有店名）；纯中文
- B4 内容量/频率：活动月更级（偶尔办）；维护者=用户本人（技术）
- B5 设备：手机/桌面各半（本地客手机找店为主场景）
- B6 约束：实体信息为虚构设定，逐字呈现；无实体商品在线销售 → **不触发**实物商品/食品合规专项
- B8 中轴 `center-axis`；区块清单见 intent-summary；三档宽度已定
- B10 技术栈输入：D1–D8 见 `tech-stack.md`

## 排除

- 排除 IA `conversion`（购买漏斗）：转化目标是到店不是下单
- 排除布局 `catalog-grid`：条目 <15，无筛选诉求
- 排除布局 `split-narrative`：无图可并置，长文不存在
- 排除布局 **`minimal-state`（锚点 glass-tech 的默认绑定）**：单屏单动作装不下「活动清单 + 到店信息」两个信息目标 → 依 layouts.md 判定顺序 2 改用 `editorial-hero` 骨架，**锚点声明的 `center-axis` 中轴保留**
- 排除布局 `utility-board`：书店主诉求是氛围感受不是高频扫读（台账语法只保留在活动列表组件内）
- 排除风格族 `craft`（warm-hospitality 等）：无环境摄影，「咖啡店→自动 warm」是本 skill 点名的陷阱
- 排除风格族 `contemplative`（quiet-luxury / japanese-ma）：前置硬条件「高质量素材」不成立
- 排除风格族 `editorial`（印刷浅底语法）：与用户点名的黑底霓虹硬约束直接冲突
- 排除锚点 `cyber-terminal`：等宽中文长文不可读（锚点库自带 never）
- 排除动效风格 Orbitron/扫描线/故障感：用户明确要去科幻感
- **记录一处 never 覆盖**：锚点 `glass-tech` 自带 `never: 非科技品类`。本站品类是书店（非科技），但①主体是魔法科技都市的虚构设定（海克斯/皮尔特沃夫）②用户在 Grill 中明确点名保留该风格的黑底霓虹调调。**判定：用户明确的风格要求覆盖该 never**，并已在 G2 落定中单独请用户确认。其余 never（不打印、无长文页）遵守。

## 剩余空间

- 技术栈：只剩 `plain-html` 领先（得分 6），`astro` 次之（3）——按定序取首
- IA：单页三区块（活动/书店/到店）+ hero——conversion 被转化目标排除，portfolio 被无作品排除
- 布局：只剩 `editorial-hero`（minimal-state 被信息目标排除、catalog/split 被密度与无图排除）
- 风格：约束「黑底+霓虹+无图+无长文+感受型」筛后仅剩 techno 族 `glass-tech` 满足全部硬约束，取 `glass-tech`，因为它是不依赖图片素材、以光效与玻璃质感成立视觉的唯一候选锚点
- 字体：骨架= Sora × Inter × JetBrains Mono（fonts.json glass-tech 条目）；**锚点特化**：中文 display 叠加宋体系衬线（`--font-display-cjk`），依据=用户点名「标题字体要有文学气质」；字重总数仍 ≤2（400/600）

## 视觉签名（≥3 条结构级，灰度仍成立）

1. **超大渐变衬线标题压过首屏，整块流光入场**——hero 店名「虚空典籍」四字，宋体 + 紫→粉青渐变 + 霓虹光晕，见首屏（原方案逐字入场，实测 Chromium 中子元素动画打断渐变字光栅，收敛为整块入场）
2. **活动台账**：等宽编号 01/02… 左置 + 日期右对齐成列（tabular-nums），当前/最近一场行玻璃卡底 + 左侧霓虹描边——见 #events 列表
3. **悬挂眉标系统**：每区块标题上方悬挂字距 0.08em 的小号青色标签，前置短横线延伸——见各 section 标题
4. **竖排引文侧栏**：#about 右缘竖排（writing-mode: vertical-rl）文学引文，窄屏收起——见书店区
