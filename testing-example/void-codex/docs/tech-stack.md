# 技术栈选型 — 虚空典籍书店站

> 依据 website-style-router v0.6.0（scripts/pick_stack.py）

## 输入判定（D1–D8）

| # | 判定项 | 取值 | 依据 |
|---|---|---|---|
| D1 | 页面规模 | `single`（单页长滚：hero / 活动 / 书店 / 到店） | 转化目标=到店+查活动，内容量小；MVP 先跑通（B2/B7） |
| D2 | 交互复杂度 | `light`（粒子背景 canvas、滚动显现、锚点导航、数据渲染列表） | 参考站气质需要氛围动效，但无状态机/筛选/表单 |
| D3 | 维护者 | `tech` | 用户答复「我自己维护，能改文件跑命令」 |
| D4 | 内容数据源 | `single-json`（活动列表单一数据文件） | 活动偶办偶更，加一场=改一个文件 |
| D5 | 交付形态 | `standalone`（新建子目录独立站） | 用户指令「新开一个子文件目录开始工程」 |
| D6 | 多语言 | `none`（纯中文） | 老城区中文书店受众；参考站的双语切换器不学 |
| D7 | 渲染需求 | `static`（无登录/表单提交/实时数据） | 到店信息 + 活动展示，均为静态内容 |
| D8 | 性能预算 | `normal` | 氛围站首屏体验重要，但无重运行时需求 |

## 结论

选定：**`plain-html`**（`index.html` + `css/` + `js/` + `data/`，零构建）

`pick_stack.py` 得分 6/7 候选第一：单页无需路由（+3）、轻交互原生 JS 够用（+2）、数据简单运行期读取（+1）。

## 被排除项

- `astro` —— 被 D1 排序压制（单页用 SSG 偏重，-1）；无被硬排除的判据，是定序落后而非不可用
- `next` / `nuxt` —— 被 D7 排除（纯静态无 SSR 需求）+ D8（框架运行时是负债）
- `eleventy` / `hugo` —— 单页无需静态生成器；模板语言学习成本无回报
- `vite-vanilla` —— D2 为 light 非 heavy，构建工具无增益

## 该栈的落地约束

- 构建：无。`index.html` 双击即可预览；部署任意静态托管
- **活动更新方式：改 `data/events.js`**（`window.VOID_EVENTS` 数组）。用 JS 数据文件而非 `.json`，因为 `file://` 直开时 `fetch` 受 CORS 限制——这是「单一数据文件」承诺在零构建栈上的等价实现
- 字体加载：自托管 woff2 + `font-display: swap` + `<link rel=preload>`（不用 `@import`）；中文走系统栈（字库 3–8MB 不可自托管）；中文衬线 display 经 CDN 引入并带完整系统回退（宋体系），加载失败不塌样
- 粒子背景 canvas 必须 `prefers-reduced-motion` 降级为静态星点

## 证伪条件（可观测）

1. 若页面需要拆成 **≥3 个独立 URL**（如活动详情页、书评页）→ D1 判错，回退 `astro`
2. 若活动需要**筛选/搜索/报名表单/报名名额状态**任一项 → D2 低估，评估 `vite-vanilla`
3. 若首屏 JS 主线程耗时使 **LCP > 2.5s（4G 中端机）**或粒子帧率 < 30fps → 砍 canvas 改纯 CSS 星点，D8 判错
