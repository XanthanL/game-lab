# 技术栈选型 — 屿光摄影（T04）

> skill 版本：website-style-router 0.9.1 ｜ Phase 1.5 产物 ｜ `pick_stack.py` 实跑记录

## 输入判定（D1–D8）

- **D1 页面规模：single** —— `pick_pages.py` 判定（7 张浅条目、无并列独立主题、非技术维护者 + 无静态生成器否决多页）
- **D2 交互：light** —— 瀑布流筛选 + 灯箱 + 移动导航，原生 JS 够用；预约表单走第三方表单服务（form endpoint）
- **D3 维护者：nontech** —— 主理人老陈，工作室 2–3 人，无技术背景（fixture「工作室介绍」：两三个人、每一单都自己拍）
- **D4 数据源：inline** —— 内容一次性交付、几乎不更新；作品集与价格直接写在 HTML 内（改文字 = 改 HTML 里对应几行，对非技术者最直白）
- **D5 交付形态：standalone** —— 给客人直接看的独立站，无宿主站
- **D6 多语言：none** —— 海边小城本地客群，纯中文
- **D7 渲染：static** —— 客户要的"在线支付/实时档期/短信通知"在 Grill 中已判定为能力边界外的需求，走降级方案（见 content-profile），不因此引入服务端
- **D8 性能预算：normal** —— 摄影站以图为主，图片已压缩至 1.5MB 总量；不设 <100KB JS 的硬预算

## 结论

选定：**`plain-html`**（`pick_stack.py` 得分 8，唯一候选）

因为：维护者非技术（D3）→ 排除一切需要 Node/命令行的方案；单页（D1）→ 无需路由与模板复用；
交互轻（D2）→ 原生 JS 够用；数据简单（D4）→ 无需构建期数据层；性能预算 normal（D8）→ 无运行时负担，双击即开。

## 被排除项（`pick_stack.py` 输出原样）

- `astro` —— 被 D3 排除（非技术维护者无法运行 npm install / 命令行）
- `eleventy` —— 被 D3 排除（同上）
- `next` —— 被 D3 排除（同上；且无 SSR 需求，D7）
- `nuxt` —— 被 D3 排除（同上）
- `hugo` —— 被 D3 排除（同上，且 Go 模板学习曲线对非技术者是硬墙）
- `vite-vanilla` —— 被 D3 排除（同上）

## 该栈的落地约束

- 构建命令：**无**（双击 `index.html` 即可预览）
- 内容更新方式：直接编辑 `index.html` 中的文字/图片标签；每次替换作品图 = 换 `assets/` 同名文件
- 字体加载：自托管 woff2（`assets/fonts/`，Baloo 2 600 + Nunito 400/600，共 52KB）+ `font-display: swap`；
  中文走系统栈（`--font-cjk` 回退 PingFang SC / Microsoft YaHei），不拖几 MB 中文字库
- 部署：任意静态托管；**中国大陆访问需 ICP 备案**（页脚 `[待填]`）

## 证伪条件（可观测，任一成立即回头改判）

1. 若老陈（或任何继任维护者）需要客人**在线选定并锁定具体档期**、或要微信/支付宝自动收款 → 纯静态做不到，必须回退补后端/小程序方案（D7 判断被推翻）
2. 若作品集真实授权照片到位后**超过 12 件且每件多图**、或新增"客片精选""拍摄攻略"等并列板块 → 单页压不住，应升 `astro` 多页（D1 判断被推翻）
3. 若上线后首页 JS 体积 > 100KB 或首屏 LCP > 4s（4G 实测）→ 说明引入了不该有的运行时/未压缩大图，违反 D8/D4
