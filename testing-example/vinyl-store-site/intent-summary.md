# Intent Summary — 二手唱片库存查询站

## 意图摘要（intent-summary）

- **源材料**：CSV 表格（`库存.csv`，1 表 41 行 = 表头 + 40 条库存，9 列）→ `extract_source.py` 提取 → 溯源见 `source-map.md`
- **交付形态**：`standalone` 独立单页（无宿主站）
- **成功定义**：客人不用问店主，自己 10 秒内查到「有没有货、什么版本、多少钱」；店主每周日更新表格后 2 步内让网站跟着变
- **转化目标**：`到店`（查到想要的 → 到店买/预留；主动作是**查询**，无线上下单）
- **图文策略**：图片=**不要**（源里没有图，二手单件拍照不可持续；排版与数据本身撑视觉，`imagePolicy: forbidden`）；图标=**functional**（状态用文字标签 + `●○→` 等宽字形，不用 emoji）
- **语言策略**：纯中文 UI；数据内容中英混排（艺人/专辑名）；默认 zh；无切换器
- **参考站**：无（用户未提供）→ 从锚点库推导
- **技术栈**：`plain-html`（D1–D8 判定与被排除项见 `tech-stack.md`）
- **中轴**：`left-rail`（锚点 swiss-utility 声明，一切 flush-left）
- **区块与尺寸**：
  - 区块：① 顶栏（店名占位 + LIVE 更新戳）要 ② 搜索 + 筛选工具条 要 ③ 台账主表 要 ④ 品相/价格说明行 要 ⑤ 页脚（更新时间 + 到店信息占位）要 ⑥ **Contact 区块 不做**（默认不做；到店信息并入页脚一行）
  - 主图/肖像/封面三档宽度：**不适用**（无图）
- **硬约束**：
  - 周更流程必须「拖一下 CSV = 完成」，零安装零命令行（用户明说不会写代码）
  - 数据缺失不编造：空价格（V-007）显示「到店询价」；店名/地址/营业时间 `[待填]` 显式占位
  - 合规：不出现极限词；品相说明写清是店主人工评定；「库存以到店实物为准」

## 待补（指不回源的内容）

| 字段 | 现状 | 需谁提供 | 页面上如何标记 |
|---|---|---|---|
| 店名 | 无 | 用户 | 顶栏显示占位「[店名待定]」，页脚同 |
| 地址 / 营业时间 / 联系方式 | 无 | 用户 | 页脚一行 `[待填]`，红色虚线框标记 |
| 价格币种 | 数字无单位 | 用户确认 | 按「推断：人民币 ¥」处理，G2 一并确认 |
| 品相评定说明文案 | 源里只有档位名 | 用户校对 | 按二手唱片通用品相写法起草，标注待店主校对 |

## 剩余空间（收敛结论）

- **技术栈**：只剩 `plain-html`，因为 D3=nontech 排除了其余全部 6 个候选（详见 tech-stack.md）
- **IA**：只剩 `directory`（高频更新的单一数据源清单），因为叙事型（narrative/portfolio）被「扫读比对」诉求排除，conversion 被转化目标=查询而非下单排除
- **布局**：只剩 `utility-board`，因为锚点 swiss-utility 绑定它，且无图（排除 editorial-hero / catalog-grid / split-narrative）、多区块（排除 minimal-state）
- **风格**：满足 [视觉资产弱] + [快速扫读] + [维护者非技术] + [实用高频] 四条 when 的锚点取 **swiss-utility**，因为它是 grid 族中唯一以「状态台账」为核心语义的锚点——本站的核心信息正是状态（在架/已售/已预留）
