# 技术栈选型 — 二手唱片库存查询站

> 选型依据：website-style-router skill v0.8.0（scripts/pick_stack.py 实跑）

## 输入判定（D1–D8）

| # | 判定项 | 取值 | 依据 |
|---|---|---|---|
| D1 | 页面规模 | `single` | 单一主动作（查库存）；40 条数据一页承载（Grill Q5/Q12，源=CSV 40 行） |
| D2 | 交互复杂度 | `light` | 搜索框 + 3 个筛选维度 + 行过滤渲染，原生 JS 足够（Grill Q14–Q16：无通知、无实时） |
| D3 | 维护者技术程度 | `nontech` | 用户原话「我不会写代码」，每周日只做「导出表格」（Grill Q13/Q24，**排除力最强**） |
| D4 | 内容数据源 | `single-json`（单一数据文件） | 周更单源 CSV → 构建期转换为 `data.js` 单文件，运行期 `<script>` 读入（源材料唯一：库存.csv） |
| D5 | 交付形态 | `standalone` | 全新独立页，无宿主站（Grill Q0b/Q23） |
| D6 | 多语言 | `none` | 纯中文 UI；数据本身中英混排（Grill Q11） |
| D7 | 渲染需求 | `static` | 无登录/表单/实时数据（Grill Q26） |
| D8 | 性能预算 | `lean` | 客人手机访问为主，首屏 JS 目标 <100KB（Grill Q14） |

## 结论（pick_stack.py 实跑输出）

选定：**`plain-html`**（得分 10，唯一存活候选）
因为：单页，无需路由；交互轻，原生 JS 够用；非技术维护者，零构建；数据简单，运行期读取即可；首屏预算紧，无运行时。

```
候选排序
  1. plain-html    纯静态 HTML + CSS     得分 10
被排除（全部被 D3=nontech 排除：维护者不能碰命令行 / Node 构建链）
  × astro / eleventy / next / nuxt / hugo / vite-vanilla
```

## 该栈的落地约束

- **构建命令：无。** 双击 `index.html` 即可预览（数据走 `<script src="data.js">`，file:// 下同样可用；这是放弃运行期 fetch CSV 的原因——file:// 下 fetch 被 CORS 拦截，非技术用户双击打开就"白屏"是最贵事故）
- **内容更新方式（核心 UX，按"最傻瓜"设计）**：
  1. 周日在表格软件里改库存 → 导出/另存为 CSV（文件名随意，编码 UTF-8 或 GBK 均可）
  2. 把那个 CSV **拖到 `更新网站.bat` 图标上松手** → 自动生成新 `data.js`，窗口显示「✓ 更新完成，共 N 条」
  3. 把整个文件夹上传/拖到托管平台（或先用双击 index.html 本地核对）
  - 转换器 = Windows 自带 PowerShell（update.ps1），零安装零依赖；Import-Csv 解析带引号字段（源数据 V-031 备注 `"日版, 带侧标"`）
  - 前端按**表头名**映射字段，不按列序；未知状态/格式/品相值原样显示不崩溃；空价格显示「到店询价」
- **字体加载：自托管 woff2**（fonts.json `loading: "self"`）：Archivo / Inter / IBM Plex Mono 各 400+600 的 latin 子集放 `assets/fonts/`，`font-display: swap`；中文走系统栈回退（中文字库 3–8MB 不自托管）
- **部署：任意静态托管**（无服务端依赖）。托管去向为 C 类待定，交付附两条傻瓜路线（腾讯云 COS 国内稳 / Netlify Drop 免费），选择不影响本次构建产物

## 证伪条件（可观测）

1. 若店主的周更流程实际需要 **>2 步**或需要安装任何软件 → 数据管线设计错误，重做转换器（目标：拖一下 = 完成）
2. 若库存增长到 **500 条以上**且客人反馈卡顿/翻不到 → D1/D4 判断失效，回退重选型（评估前端分页或构建期渲染）
3. 若出现**第 7 个页面**的需求（如按流派分页/活动页）→ D1 判断错误，应迁移到 `astro`
4. 若部署后首屏 JS（app.js + data.js）实测 **>100KB** → 违反 D8，检查是否混入了运行时
