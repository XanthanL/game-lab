### 数据特征（设计输入）
- 客人问的「什么版本」没有独立列，版本信息分散在「备注」（自由文本）+「年份」+「品相」→ 搜索必须覆盖 艺人/专辑/年份/备注 全字段
- 1 条无价格（V-007 唐朝，备注"价格待标"）→ 前端显示「到店询价」，**不编造数值**（D 类红线）
- 「已预留」条目附取货备注 → 显示状态即可，不渲染客人隐私细节？→ 备注是店主自己写的业务备忘，照常渲染（源里就是这么记的），无敏感个人信息
- 无图片列 → 图文策略只能走「无图排版」

## 每周更新带来的前瞻性要求
店主每周日重新导出 CSV → 列顺序/列名/取值可能漂移。落地约束：
1. 前端按**表头名**映射字段，不按列序号
2. 未知状态/格式/品相取值 → 原样显示，不崩溃、不丢行
3. 编码自适应：Excel/WPS 中文 Windows 默认导出 GBK（ANSI），新版有 UTF-8 选项 → 转换器两种都要能读
4. 行数变化（增删）不影响结构
