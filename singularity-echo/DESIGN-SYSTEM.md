# 奇点回响 · 设计系统

> Phase 0 产出。与 `.impeccable.md`（设计上下文）配套使用。
> **单一事实源**：CSS `:root` 变量。JS 启动时读一次缓存，不重复定义。

## 一、现状诊断（Phase 0.2 实测数据）

| 维度 | 现状 | 问题 |
|---|---|---|
| CSS 变量 | 8 个（`--bg --ink --dim --cyan --amber --red --panel --line`） | `--bg` / `--ink` / `--panel` 各只被引用 **1 次** —— 定义了但没用 |
| 硬编码色值 | CSS **44** 个 hex + **24** 个 rgb 三元组；JS **53** 个 hex + **35** 个 rgb 三元组 | 最典型的 `111,231,255` 手写了 **61 遍**（= `--cyan` 的值） |
| 字号 | **30** 个不同值 | 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 全挤在一起，靠手调 |
| 字距 | **19** 种 | `.04em` ~ `.5em` 无阶梯 |
| z-index | **12** 个（1–10 连续 + 30 / 40） | 无层级语义，新增元素只能猜 |
| 时长 | **26** 处，`.11s`~`1.6s` | 无档位；含 `cubic-bezier(.2,2.4,.4,1)` 这种过冲 2.4 的弹性曲线 |
| 描边 | canvas `lineWidth` **36** 个不同值 | 无阶梯 |
| 媒体查询 | 4 个（reduced-motion / pointer:coarse / max-width:640px / hover:hover） | ✅ 这部分是好的，保留 |

**结论**：不是"没有设计"，是"设计只存在于作者的手感里，没落到系统里"。所以每次加东西都要重新手调，
风格自然漂移。

## 二、方向提案

### 主推：星图测绘 / Celestial Cartography

**视觉语言取自古代航海图与星图，而不是现代科幻霓虹。**

| 层面 | 定义 |
|---|---|
| 底色 | 深墨蓝，大面积负空间（B.1 修订：提亮近 3 倍） |
| 线条 | **冷钢蓝** —— 测绘仪器的结构与刻度线（B.1 修订；初版为暖纸白） |
| 文字 | **中性铅白** —— 刻度与读数，已去黄（B.1 修订） |
| 强调色 | **朱砂**，全画面唯一高饱和色，只用于危险 / 奇点 / Boss |
| 六船体 | **天然矿物颜料色板**：石青 / 朱砂 / 赭石 / 石绿 / 铅白 / 紫 |
| 图形语言 | 刻度环、坐标网格、发丝分隔线、方位标记、极细端点收束 |
| 动效性格 | 慢、稳、有质量感；爆发集中在极短的一瞬 |

**为什么是它**

1. **有辨识度**：市面上没有任何太空射击游戏用"航海测绘"语言。青紫霓虹满地都是，矿物颜料几乎没有。
2. **与主题自洽**：游戏已有 `logbook`（航行日志）、名字叫"奇点**回响**"（观测与记录）——
   测绘语言不是外加的装饰皮，是内容本身的延伸。
3. **治"堆元素"的病**：这个方向的质感来自**线条精度**（对齐、粗细、收束），
   而不是光晕叠加。它天然要求少元素、高确定性的构图。
4. **技术上便宜**：细线、网格、刻度在 Canvas 里是低开销绘制，比大量 radial gradient 光晕更省。
5. **天然支撑"孤独壮阔"**：星图 = 一个人在巨大尺度上的位置记录。

**代价（要认）**

- 需要把 canvas 里 88 处颜色字面量迁移到 token，工期集中在这个方向。
- 现有的"到处发光"习惯要改：高饱和必须变成事件而非常态，玩家初期可能觉得"变暗了"。

### 备选 A：黑体辐射 / 光谱

颜色由**色温**推导（2000K 橙红 → 12000K 蓝白），运动反馈用多普勒红移/蓝移。
物理真实感极强，但色域偏冷偏"科学"，且难以承载六船体的区分需求。

### 备选 B：Solaris 近乎单色

全灰阶 + 唯一一个事件色。最克制、最快能做出一致性，
但战斗反馈的辨识度会变难（敌我弹幕靠明度区分不够），对"正式独立游戏"目标风险偏高。

## 三、Token 架构

### 命名规范

`--c-*` 颜色 · `--fs-*` 字号 · `--lh-*` 行高 · `--ls-*` 字距 ·
`--dur-*` 时长 · `--ease-*` 缓动 · `--lw-*` 线宽 · `--glow-*` 发光强度 · `--z-*` 层级

**颜色成对定义**：hex 给 CSS 用，`-rgb` 分量给"需要拼透明度"的场景用
（CSS 写 `rgb(var(--c-ink-rgb) / .58)`，JS 读 `-rgb` 后拼 `rgba()`）。

```css
:root{
  /* ── 基底 · 星图墨 ───────────────────── */
  --c-void:#05070a;  --c-void-rgb:5 7 10;        /* 最底层：覆盖层、画布底 */
  --c-bg:#0a0d12;    --c-bg-rgb:10 13 18;        /* 舞台背景 */
  --c-panel:#0a0d12; --c-panel-rgb:10 13 18;     /* 面板（配 alpha 使用） */
  --c-line:#e8e2d4;  --c-line-rgb:232 226 212;   /* 网格 / 分隔线（低 alpha） */

  /* ── 文字 · 铅白 ─────────────────────── */
  --c-ink:#e8e2d4;   --c-ink-rgb:232 226 212;    /* 主文字、细线、船体描边 */
  --c-ink-2:rgb(232 226 212 / .58);              /* 次级文字 */
  --c-ink-3:rgb(232 226 212 / .34);              /* 三级 / 禁用 */

  /* ── 强调 · 朱砂（全画面唯一高饱和） ──── */
  --c-cinnabar:#c0402b;   --c-cinnabar-rgb:192 64 43;
  --c-cinnabar-hi:#e0573c;--c-cinnabar-hi-rgb:224 87 60;

  /* ── 状态 ─────────────────────────────── */
  --c-danger:#c0402b;  --c-danger-rgb:192 64 43;
  --c-warn:#c08a3e;    --c-warn-rgb:192 138 62;
  --c-safe:#4a7c59;    --c-safe-rgb:74 124 89;

  /* ── 六船体 · 矿物颜料 ────────────────── */
  --c-hull-peregrine:#3b6ea5;  /* 石青 —— 隼 */
  --c-hull-rapier:#c0402b;     /* 朱砂 —— 轻剑 */
  --c-hull-bulwark:#4a7c59;    /* 石绿 —— 壁垒 */
  --c-hull-raven:#6b4b7a;      /* 锰紫 —— 渡鸦 */
  --c-hull-swarm:#c08a3e;      /* 赭石 —— 蜂群 */
  --c-hull-nemesis:#e8e2d4;    /* 铅白 —— 回响（终局船无色，象征奇点本身） */
}
```

### JS 侧消费方式（单一事实源，不重复定义）

```js
/* 启动时读一次 CSS 变量并缓存；游戏无明暗主题切换，读一次即够 */
const _cv = n => getComputedStyle(document.documentElement).getPropertyValue(n).trim();
const PAL = {};
for(const k of ['void','bg','panel','line','ink','cinnabar','cinnabar-hi',
                'danger','warn','safe',
                'hull-peregrine','hull-rapier','hull-bulwark','hull-raven','hull-swarm','hull-nemesis']){
  PAL[k] = _cv('--c-'+k+'-rgb').replace(/\s+/g,',');   // '232,226,212'
}
const RGBA = (k,a)=>`rgba(${PAL[k]},${a})`;
```

> ⚠️ 上表是**阶段 B 的目标收敛集**。阶段 A 实际落地的是 1:1 保真的 **90 个 token**
> （见 `index.html` 的 `:root`），因为"等价替换"不允许合并任何值。
> 阶段 B 会把这些 token 的**值**改向星图色板，届时多个 token 会指向同一值，
> 收敛就自然发生了 —— 不需要删 token。实际 PAL 键表以 `index.html` 中的
> `NAMES` 常量为准（24 个），它只列 JS 真正消费的那批。

**迁移策略：两阶段，先等价再改值。**

1. **阶段 A（零视觉变化）**：把硬编码值替换为 token 引用，token 的**值就是现在的值**。
   跑一次截图对比，确认像素级无差异。此阶段可随时中止，风险为零。
2. **阶段 B（换方向）**：只改 `:root` 里的 token 值。
   因为所有引用都指向 token，视觉会整体切换 —— 这一步才是"换风格"。

| Token | 值 | 用于 / 吸收的旧值 |

| `--dur-2` | 120ms | 快速状态切换：HUD 数值、悬停（← .11 / .12s） |

环境氛围类**不进入时长档**（星空漂移、背景呼吸、刻度环自转），
单独按 `--ambient-*` 管理，量级 800ms–120s，曲线用 `linear` 或 `ease-in-out`。

**禁止项**（写成自查清单）

- ✗ `transition: all` —— 永远点名具体属性
- ✗ `ease-in` 用在 UI 上 —— 它延迟了用户最关注的那一瞬
- ✗ `scale(0)` 入场 —— 用 `scale(0.95)` + `opacity: 0`
- ✗ 表外的时长/曲线 —— 需要新的就先加进表里
- ✗ 键盘触发的高频操作加动效 —— 100+ 次/天的动作不动画
- ✗ 动画化 `width` / `height` / `margin` / `padding` / `top` / `left`
- ✗ `:hover` 动效不加 `@media (hover:hover) and (pointer:fine)` 门控
- ✗ 忘记 `prefers-reduced-motion` —— 要更柔和的变体，不是直接归零

### 表 3b · 打击反馈参数（Phase 1 落地 · 2026-09-10）

打击反馈是"手感"的 80%，但它的时间尺度**不进通用时长档** ——
通用档最细是 110ms，而打击要的是 30–160ms 量级。单独一张表管。

**伤害飘字四档**（`dmgText(x,y,val,kind,key)`）

| kind | 触发 | 颜色 | 字号 | 生命 | 上浮 | 位置偏移 | 特殊 |
|---|---|---|---|---|---|---|---|
| `hit` | 普通命中 | `--c-ink` | 11px | 0.8s | 26px/s | y −6 | 同目标合并累加 |
| `crit` | 暴击 | `--c-amber-hi` | 17px | 0.9s | 36px/s | y −30 · x +12 | 落位弹跳 160ms（1.62× → 1×） |
| `weak` | 弱点 / 要害 | `--c-cyan` | 12.5px | 0.85s | 30px/s | y −14 | 斜体 |
| `absorb` | 被挡 / 被吸收 | `--c-steel` | 10.5px | 0.7s | 18px/s | y −6 | 钢灰 + 扩散光环 |

三条必须记住的规则：

1. **合并**：同 `key`（实体对象）+ 同 kind 在存活期内只留一条，数值累加、位置跟随、动效复位。
   连射一秒十几发，逐发开条会糊满屏幕。（实测：8 目标 × 6 次命中 = 48 次 → 只剩 16 条）
2. **上限** `DMG_MAX = 26`：超出时挤掉最旧的**非暴击**条；若全是暴击，宁可不显示新条。
3. **分离**：`crit` 相对 `hit` 必须**横纵同时拉开**。纯纵向分层不够 —— 17px 与 11px 的字
   垂直差 14px 时仍咬成一团（实测）。上面的偏移量是按这个结论定的，别随手改小。
4. 伤害数字**描一圈底色**（`RGBA('void',.9)`，线宽 2）再填 —— 它经常压在敌机 /
   Boss 红色核心上，不描边在那个背景里读不出来。得分 / 拾取类飘字不描边（保持轻量）。

**得分飘字必须离开本体**：`killEn` / `killAst` 的 `+分数` 上移到 −28 / −32px。
实测它和伤害数字同点时会对冲成一个读不出的色块。

**命中音效四档**（`sfx.hit(kind)`）

| 档 | 音色 | 节流 | 设计意图 |
|---|---|---|---|
| 普通 | square 230→120Hz · 50ms · g .038 | 70ms | 低频闷「噗」，连射时不抢耳 |
| 暴击 | triangle 660→1180Hz + sine 1320→1720Hz · rv .16 | **90ms 独立窗口** | 高频亮「叮」上行；**不被普通档节流吃掉** |
| 被挡 | noise 5400→1900Hz + square 430→300Hz | 与普通共用 70ms | 金属「嚓」，无音高感 |
| 击杀 | 复用 `sfx.boom(sz)` | — | 低频「轰」 |

验收口径：**关掉音效也能靠视觉读懂"打中了 / 暴击了 / 盾吃掉了"**；
开音效时四种可盲听区分。

**击杀镜头三级**（`killImpact(e)` 单一出口，各类敌人不再各写一套）

| 级 | 触发 | 顿帧 | 镜头 kick | 泛光 | 色差 |
|---|---|---|---|---|---|
| 轻 | 普通小怪 | 0 | — | — | — |
| 重 | 重型 / 精英词缀 | 0.05s | 0.012 | 0.55 | — |
| 爆 | 新星 / 幽灵 / 爆裂词缀 | 同上 | 0.032 / 0.02 | 1 / 0.85 | 0.85 / 0.5 |

### 表 4 · 描边与发光强度

**线宽**（canvas `lineWidth` 36 个值 → 5 级）

| Token | 值 | 用于 |
|---|---|---|
| `--lw-hair` | 0.6 | 辅助线、网格、刻度 |
| `--lw-1` | 1 | 常规描边：HUD 边框、卡牌边 |
| `--lw-2` | 1.6 | 主体轮廓：船体、敌人 |
| `--lw-3` | 2.4 | 强调轮廓：Boss、选中态 |
| `--lw-4` | 5 | 外发光描边（船体外柔光） |

**发光强度 —— 用 alpha 分级，不用 blur 半径区分**

| Token | alpha | 用于 |
|---|---|---|
| `--glow-1` | .14 | 常态环境光（几乎看不见） |
| `--glow-2` | .30 | 常规元素外发光 |
| `--glow-3` | .55 | 活跃 / 选中 |
| `--glow-4` | .85 | 爆发 / 危险 |

> **核心原则**：想让东西"更亮"，提高 alpha，**不要加大 blur**。
> blur 越大越糊，是廉价感的来源。

## 六、阶段 A 实施记录（2026-09-10 完成）

### 落地了什么

| 项 | 迁移前 | 迁移后 |
|---|---|---|
| CSS 字面色值 | 44 hex + 24 rgb（散在 500 行里） | **0**（:root 之外） |
| JS 语义色字面量 | 青 ×61 / 琥珀 ×23 / 危险 ×6 … | 走 `PAL` + `RGBA()`，共 **20** 处调用 |
| token 总数 | 8 个（3 个基本没被用） | **90 个**（颜色 + 层级，值 = 原值） |
| 自查 | 无 | `node audit-tokens.js` 四条规则，退出码即结论 |

### 范围边界（重要，决定了阶段 B 要做什么）

**本次迁移的**：所有 CSS 颜色、CSS 里的 z-index、JS 里语义明确的强调色
（青 / 琥珀 / 危险 / 满级金 / 青高亮 / 底色）。

**故意没迁的**（阶段 B 处理）：

- **字号 / 时长 / 字距** —— 这三样的价值来自"归并档位"，而归并必然改变视觉，
  不属于等价替换。直接在阶段 B 按表 2 / 表 3 改，不必先铺 token。
- **实体色板** —— `HULL_TINT`（6 船体）、`BOSS_STYLE`、敌人机体填充、粒子 `cols`。
  它们是**内容数据**，已经各自集中在一张表里（本身就是单一事实源），
  阶段 B 整表换成矿物色板即可，逐个进 token 只会增加一层无谓间接。
- **VFX 色阶** —— 各类爆炸/拖尾的数值渐变。同理。

自查脚本 R4 把上述"允许保留的字面量"显式列成白名单：
**任何新增的语义色都会被拦下**（必须先加进 `:root` 再用 `PAL`）。

### 怎么证明"零变化"

截图肉眼看不算证明 —— 星空在漂移、面板有 `backdrop-filter`、CSS 有无限动画，
两次截图必然不同。用了两把尺子：

1. **computed style 逐条比对**（迁移前 / 后各跑一次同一份 DOM 探针）
   → **13189 条断言，0 条不同**
2. **确定性像素比对** → 冻结时钟（`performance.now` 按 1/60s 步进）+ 固定随机种子
   （`Math.random` 换定种子 LCG）+ 到达目标帧后停掉 rAF 并禁用 CSS 动画
   → **1,024,000 个像素，0 个不同**

第 2 项的脚本已固化为项目工具，以后任何"应当不改变画面"的重构都用它：

```bash
cp ../.workbuddy/backups/singularity-echo_<回退点>.html singularity-echo/_pre.html
node .workbuddy/shots/zero-diff.js singularity-echo/_pre.html singularity-echo/index.html
# diff=0 → 安全；diff>0 → 会打印差异区域坐标，据此定位被动到的是哪一层
```

⚠️ 工具的一条硬约束：**每个文件必须用全新浏览器实例截图**。
`file://` 协议下 localStorage 跨 context 共享，游戏的 `nova-*` 存档会被上一个页面
写入后污染下一个页面，制造出假的像素差异（实测踩过：11106 px 假差异）。

### 迁移中真实踩到的坑（都已在代码里修掉）

1. **内联样式里的旧变量名**：HTML 上 `#vicBonus` 有 `style="…color:var(--amber)"`，
   只改 `<style>` 段会漏掉它 → 颜色静默退回继承值。**这是唯一一处真实回归，
   被 computed style 比对抓到。** 教训：改变量名要全文件扫 `var(--旧名)`。
2. **`'rgba(...)'` 被替换后引号残留** → `'RGBA('cyan',0.4)'` 直接语法错误。
   批量替换普通字符串时必须把外层引号一起吃进去。
3. **token 缺 `-rgb` 伴生变量**：`#ffe9a8` 换成 `RGBA('amber-hi',…)`，
   但 `--c-amber-hi` 只有 hex 没有 `-rgb` → PAL 取不到值，运行时回退成品红。
   **规则：凡是要给 JS 用的颜色，必须在 `:root` 里成对定义。**
   这一条现在由自查 R3 自动把关。

### 踩到的两个坑（都已修）

1. **z-index 不能一刀切压平。** `--z-local-1/2/3`（组件内部层叠上下文）和

   原来的相对先后被破坏。**正确做法：全局分档，档内保留相对序号**（0 / 1 / 2）。
2. **全局替换色值会撞车。** 批量把敌人色改成矿物色时，`255,215,94`（拟态体的色）
   恰好等于旧 `--c-amber` 的值，一次替换波及 37 处"金色 VFX"。
   **教训：换色前先 `grep -c` 每个旧值，出现次数远超预期的就是撞车。**

### 引导条 `#guide`（2.1 · 首局分步引导）

| 属性 | 取值 | 理由 |

| 主文案 | `--c-ink-hi` · `--fs-3` · 字距 .1em | 中性铅白 = 读数 |
