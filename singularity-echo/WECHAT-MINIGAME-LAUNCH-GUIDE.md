## 0. 先回答你第一个问题：还有要开发的地方吗？

**有，而且移植本身就是主体工程 —— 不是「准备一下就能上架」。**

你现在的 `index.html` 是一个**纯浏览器 H5 游戏**。微信小游戏**没有 DOM**。
小游戏运行时只有一块 canvas 加一套 `wx.*` API，`document` / `window` / `localStorage`
在运行时**根本不存在**。你游戏里的菜单、机库、设置、星图、榜单、结算、卡片选择
**全是 HTML + CSS 写的**，在小游戏里一行都跑不了。

游戏逻辑层（数学 / 碰撞 / 波次 / RNG）几乎不用改，**UI 层是全部工作量**。

下面的数字是我今天当场量出来的（不是估的）。

### 1.2 JS 段里的浏览器 API 依赖（小游戏里全部要换）

| API | 出现次数 | 小游戏里怎么办 |
|---|---:|---|
| `addEventListener` | **95** | → `wx.onTouchStart/Move/End`、`wx.onKeyDown` 等 |
| `innerHTML` | **51** | ❌ 没有 DOM，UI 必须重画 |
| `classList` | **51** | ❌ 同上 |
| `localStorage` | **60** | → `wx.setStorageSync` / `wx.getStorageSync`（机械替换，最容易） |
| `document.*` | **62** | ❌ 同上（含 `getElementById` / `querySelector` / `createElement`） |
| `createElement` | **24** | ❌ 同上 |
| `window.*` | **34** | 见下方细分 |
| `navigator.*` | **13** | 见下方细分 |
| `location.*` | **3** | → `wx.getLaunchOptionsSync().query` / 场景值 |
| `Audio` / `new Audio` | **4** | → `wx.createInnerAudioContext()` |
| `getContext` | **13** | ✅ 小游戏有 `wx.createCanvas().getContext('2d')`，**不用改** |
| `new Image` | **12** | → `wx.createImage()` |
| `performance.now` | **8** | ✅ 保留 |
| `requestAnimationFrame` | **7** | ✅ 保留 |

**细分：**

| 具体 API | 次数 | 小游戏替代 |
|---|---:|---|
| `window.addEventListener` | 21 | `wx.onTouchStart` / `wx.onWindowResize` / `wx.onShow` / `wx.onHide` |
| `window.matchMedia` | 4 | `wx.getSystemInfoSync()` + `wx.onWindowResize` |
| `window.innerWidth/innerHeight/devicePixelRatio` | 3 | `wx.getSystemInfoSync()` |
| `window.AudioContext` / `webkitAudioContext` | 2 | `wx.createInnerAudioContext()`（小游戏 WebAudio 受限，建议绕开） |
| `navigator.share` | 3 | `wx.shareAppMessage()` |
| `navigator.clipboard` | 3 | `wx.setClipboardData()` |
| `navigator.canShare` | 2 | 删掉（微信里恒可分享） |
| `navigator.maxTouchPoints` | 2 | `wx.getSystemInfoSync()` |
| `navigator.getGamepads` | 2 | **砍掉** —— 小游戏没有手柄 API，5.2 那套手柄支持在小游戏里用不上 |
| `navigator.userAgent` | 1 | `wx.getSystemInfoSync()` |
| `location.hash` / `search` / `href` | 3 | `wx.getLaunchOptionsSync().query`（你的 6.1 `#g=` 分享链接要改传参方式） |

**结论**：`getContext` / `performance.now` / `requestAnimationFrame` / 纯数学逻辑 ≈ **能直接跑**；
需要动的是 **95 事件 + 51 innerHTML + 51 classList + 62 document + 60 localStorage ≈ 320 处**。

### 1.3 资源体积 —— ⚠️ 这里有个硬障碍

| 资源 | 体积 |
|---|---:|
| `index.html` | 633 KB |
| `vendor/proton.web.min.js`（粒子库，MIT） | 64 KB |
| `og.jpg` / `thumb.jpg` | 127 KB × 2 |
| **`bgms/` 9 首 BGM** | **44 MB** |

**微信小游戏代码包限制：总包 ≤ 30 MB，主包 ≤ 4 MB。**

你的 BGM **44 MB，已经超了总包上限**。

我实测了一首「余晖 / Afterglow」（原 5.24 MB）的压缩比：

| 方案 | 单首体积 | 9 首推算 |
|---|---:|---:|
| 原始（约 188 kbps 立体声） | 5.24 MB | 44 MB ❌ |
| 96 kbps 单声道 | 2.80 MB | ≈ 23.5 MB ⚠️ 勉强 |
| **64 kbps 单声道** | **1.88 MB** | **≈ 15.8 MB ✅ 推荐** |
| 48 kbps 单声道 | 1.43 MB | ≈ 12.0 MB ✅ 更省 |

**结论**：BGM 统一转 **64 kbps 单声道**（≈ 16 MB），主包放代码（< 4 MB 没问题），
BGM 走**分包**按需加载，总包约 20 MB，在 30 MB 内。

> 如果你的音乐是氛围型 pad（本来就是铺底），降到 64k 单声道听感损失很小；
> 有明确旋律线的那几首可以单独提到 96k。

### 1.4 还有两个已知的适配点

- **`#g=` 分享链接**（6.1 / 6.6 的轨迹码分享）目前走 `location.hash`。
  小游戏里没有 URL，要改成 `wx.shareAppMessage({ query: 'g=xxx' })` + `wx.getLaunchOptionsSync().query`。
  **这是你游戏最核心的社交玩法，移植时优先级要排高。**
- **手柄支持**（5.2）在小游戏里没有对应 API，直接砍掉，不要为它花时间。

## 3. 合规篇

### 3.1 主体选择：个人 vs 企业

| | 个人主体 | 企业 / 个体工商户 |
|---|---|---|
| 注册成本 | 免费（微信认证约 ¥30/年，个人可选） | 营业执照 + 对公账户 |
| 免版号 | ✅ 可以走 IAA 免版号 | ✅ |
| **虚拟支付（内购）** | ❌ **不能开通** | ✅ 可以 |
| 广告变现（IAA） | ✅ 可以 | ✅ |
| 备案 | ✅ 可以用个人身份证备案 | ✅ |

**对你的情况**：你是个人开发者、0 预算、游戏是免费 + 激励视频的路子 →
**个人主体完全够用，不用去注册公司。**

唯一损失是不能做内购。但你的游戏设计本来就是「免费 + 激励视频」，
内购对你意义不大。

### 3.2 免版号：走「IAA 情况二」

这是**整个方案里最关键的一条**。官方文档的说法：

> step2：选择游戏情况
> **IAA 游戏选择「情况二：小游戏当前及未来均不需要开通虚拟支付」**
> step3：选择类目和支付资质
> - 选择与游戏内容一致的游戏三级类目
> - **选择不申请支付资质**

也就是说：**只要你承诺当前和未来都不开虚拟支付，就可以走免版号的 IAA 备案通道。**

⚠️ **这句话是有约束力的** —— 选了「情况二」，以后想加内购就得回头补版号
（版号是另一套完全不同的审批，个人主体基本拿不到）。
**所以现在就要想清楚：这游戏以后要不要卖东西？**

我的判断：你的设计（免费 + 激励视频 + 种子/轨迹码分享）天然适合 IAA，
**选情况二没有损失**。但这是你的决定。

### 3.3 软著（计算机软件著作权登记证书）

**什么时候必须提供？**（官方原文）

> IAA 游戏进行备案时，遇以下情形需要提交《计算机软件著作权登记证书》或对应其他授权材料：
> 1）**游戏名称含有英文**、或"软件"字样
> 2）涉及相关品牌、公众人物合作等

**你的情况**：如果备案名称用纯中文「奇点回响」，理论上不触发第 1 条。

**但我强烈建议你还是申请一个**，理由：
- 名称审核有解释空间，「奇点回响」虽然中文，但游戏内大量英文
  （`SINGULARITY ECHO` / `NOVA` / `TIME ATTACK`），审核员可能要求补材料；
- 软著是**你对抗抄襲的唯一低成本武器**，微信维权、应用商店投诉都要它；
- **个人自申是免费的**（中国版权保护中心自 2017 年起停征软件著作权登记费），
  只花时间不花钱。

**自申要点**：
- 渠道：中国版权保护中心（ccopyright.com.cn），走「计算机软件著作权登记」
- 材料：源代码（前后各连续 30 页，共 60 页）+ 操作说明文档 + 身份证明
- 周期：普通办理约 30–60 个工作日（可加急，加急要钱）
- 费用：**官方免费**；找代办几百到一千多，**0 预算就自己申**

⚠️ 时间上要提前规划：**软著下来之前提不了备案**，先去申，别等。

### 3.4 备案：三道关，别搞混

这是最容易晕的地方。实际是**三件事，有先后**：

```
① 小游戏备案（前置审批，省宣主管部门）
      ↓ 通过
② 小程序备案（工信部）
      ↓ 通过
③ 工信部短信核验（在②中间）
```

#### ① 小游戏备案（前置审批）

- **入口**：微信公众平台 → 设置 → 基本设置 → 小程序备案 → 去完善 → 小游戏备案右侧「前往提交」
- **前提**：
  - 资质审核（IAA）已通过（见 3.2，1–3 个自然日）
  - **适龄提示已设置并通过**（见 3.5）
- **材料**：清晰完整地介绍游戏内容（场景 / 玩法 / 功能）+ 对应截图（尺寸、版本要一致）
- **周期**：平台初审 1–2 个工作日 → 主管部门 **10–20 个工作日**

⚠️ **三条铁律**（官方反复强调，违反直接驳回或重来）：

1. **游戏名称、账号主体在任何阶段都必须与提审时保持一致。**
2. **提交后处于「审核中」或「已通过」，不允许修改名称或主体。**
   想改名？等小程序备案完成后再说。
3. **主管部门审核中，不要做任何修改操作**（改名、主体迁移都别动）。

> 也就是说：**游戏名一旦提交就锁死了，提交前想清楚。**
> 我建议现在就把名字定下来 —— 先去微信搜一下有没有同名，
> 「同名游戏已获批 / 名称重复」是最常见的驳回原因之一。

**常见驳回原因（自查用）**：
- 前置资质材料未提交或未通过
- **适龄提示未设置或未通过**
- 备案内容不合规且多次驳回未更新重提
- 备案提交后改名或做主体迁移
- 游戏名称与已获批名称重复

#### ② 小程序备案（工信部）

前置审批通过后去【小程序备案】页面。五个环节：

```
备案信息填写 → 平台初审 → 工信部短信核验 → 通管局审核 → 备案成功
```

⚠️ **工信部短信核验这一步很多人漏掉** —— 提交后工信部会发短信到你在备案信息里
填的手机号，**必须在规定时间内回复验证**，不验证就卡住。填完信息后盯短信。

#### ③ 完成后的义务

备案信息要和小程序实际信息一致。**改名或改主体后必须同步更新备案**，
长时间不一致会被限制搜索、限制新增用户注册。

### 3.5 适龄提示（备案前置，别漏）

- **依据**：《未成年人网络保护条例》《未成年人保护法》《网络游戏适龄提示》团体标准
- **入口**：微信公众平台 → 设置 → 基础设置 → 基本信息 → 适龄提示
- **设置后要提交平台审核**，通过后平台统一在启动页展示标识
- **分档**：`8+` / `12+` / `16+`

**奇点回响应该选哪档？** 按官方的评级参考：

| 档位 | 参考标准 |
|---|---|
| 8+ | 画面简约、卡通风；无复杂故事背景；无写实对抗；**无陌生人社交系统** |
| 12+ | 卡通/动漫/手绘，**无写实**；可有完整故事背景；可有一定难度对抗 |
| 16+ | **3D 写实或近写实**；宏大背景；高难度对抗 |

奇点回响是**抽象几何风格（三角飞船、粒子、星图）**，无写实画面、无剧情、
无社交系统、纯操作对抗 → **建议 `8+`**。

选 8+ 的好处：覆盖人群最广，对未成年人的限制最少。
**注意**：如果你的画面里有比较强烈的爆炸/受击红闪，审核可能要求你调到 12+，问题不大。

⚠️ 官方明确：即使你在游戏内自己加了适龄提示，**仍然要在 MP 设置**，保持一致。

### 3.6 内容合规自查（提审前自己过一遍）

小游戏内容规范里最容易踩的：

- [ ] **无涉赌**：不能有任何「开箱 / 抽卡 / 随机奖励」的暗示
      （你的 6.3 Modifier、6.4 卡池是玩家自选的，不是抽奖 ✅）
- [ ] **无诱导分享**：不能「分享得奖励」——⚠️ **你的 6.6 轨迹码分享要小心**
      是「分享我的成绩给别人挑战」（用户主动、无奖励），不是「分享领道具」，
      属于正常社交功能，但要确保文案里不出现「分享得 XX」
- [ ] **无诱导关注**：不能强制关注公众号才能玩
- [ ] **无虚假宣传**：截图和简介要与实际游戏一致
- [ ] **无侵权**：字体、音乐、美术都要有授权
      ⚠️ **你的 BGM 是谁作的？** 如果是自己做的没问题；
      如果是买的/下载的，确认授权范围覆盖「游戏发行」
- [ ] **无 UGC 风险**：你的游戏没有 UGC（用户生成内容）✅ 少一大块麻烦
- [ ] **名称合规**：不能用「三国群英」这种与内容无关的名字碰瓷

### 3.7 隐私与用户协议

- 小程序/小游戏需要在 MP 配置**用户隐私保护指引**，声明你收集了什么数据
- 你的游戏**没有账号系统、没有服务器、数据全在本地**（`localStorage` → `wx.setStorageSync`）
  → 隐私声明可以写得非常干净：**「本游戏不收集任何用户个人信息」**
- ⚠️ 如果你接了广告（IAA），广告 SDK 会采集设备信息，
  隐私指引里要体现（微信广告组件这块平台会处理，但你要在指引里勾选对应项）

### 3.8 广告合规（IAA）

- 激励视频**必须给用户明确选择**，不能强制观看
- 激励视频的奖励要**真实发放**
- 不能诱导点击广告
- 不能在广告上叠加任何遮挡

**好的做法**：死亡后「看广告复活一次」、结算页「看广告双倍星尘」——
用户主动选、奖励真实、不打断核心对局。

⚠️ **注意**：你游戏的核心是「一局跑多久/跑多远」，
**不要在局中插激励视频打断手感**，会毁掉体验。放死亡结算页最安全。

## 4. 上架流程 SOP

```
阶段 0  注册与准备          ← 现在就能做，0 成本
   ├── 注册小游戏账号（mp.weixin.qq.com，注册类型选「小游戏」⚠️ 不是「小程序」）
   ├── 定死游戏名称（提交后难改）
   └── 同步申请软著（周期长，先排队）
   
阶段 1  开发适配            ← 最大的工作量
   ├── 抽 PAL 平台适配层
   ├── UI 重写为 canvas
   ├── 音频压缩 + 分包
   └── 开发者工具跑通
   
阶段 2  提审（代码审核）
   └── 上传代码 → 提交审核（平台审代码合规性）
   
阶段 3  备案（合规审批）     ← 与阶段 2 可并行
   ├── 适龄提示设置 + 审核
   ├── 资质审核（IAA 情况二）
   ├── 小游戏备案（前置审批，10–20 工作日）
   └── 小程序备案 + 工信部短信核验
   
阶段 4  发布
   └── 备案全绿 → 发布上线
   
阶段 5  变现
   ├── 累计 UV > 500 → 开通流量主
   └── 接入激励视频
```

### 阶段 0 · 注册（重点）

1. 打开 **mp.weixin.qq.com** → 立即注册
2. ⚠️ **注册类型选「小游戏」，不要选「小程序」**
   （选错类目后面改不了，游戏必须走小游戏类目）
3. 主体选**个人**，填身份证 + 手机号验证
4. 邮箱要**全新的、没注册过微信公众平台的**
5. 注册完先**把游戏名称定下来** —— 名称一旦用于备案就锁死

### 阶段 1 · 开发适配

1. 下载 **微信开发者工具**（稳定版）
2. 新建小游戏项目，选「无 AppID」先用测试号跑通
3. 按第 6 节的做法做 PAL + UI 重写

### 阶段 2 · 提审

## 6. 移植工程篇（路线 A 怎么做）

### 6.1 第一步：抽 PAL（平台适配层）

**这是所有移植工作的前置**。PAL 把「平台差异」收口到一个文件，
以后换平台（微信 → 抖音 → 快手）只改 PAL。

PAL 至少收口这几类：

```js
// pal.js —— 平台适配层
export const PAL = {
  // 存储（60 处 localStorage 全走这里）
  get(key, def)      { ... wx.getStorageSync ... },
  set(key, val)      { ... wx.setStorageSync ... },
  remove(key)        { ... wx.removeStorageSync ... },

  // 系统信息（替代 window.innerWidth / devicePixelRatio / navigator.userAgent）
  screen()           { ... wx.getSystemInfoSync() ... },

  // 输入（95 处 addEventListener 全走这里）
  onTouchStart(cb)   { ... wx.onTouchStart ... },
  onTouchMove(cb)    { ... },
  onTouchEnd(cb)     { ... },
  onTouchCancel(cb)  { ... },   // ⚠️ 你 7.6 修的 touchcancel 坑在这里要重新验一遍

  // 音频（4 处 Audio）
  createAudio(src)   { ... wx.createInnerAudioContext() ... },

  // 分享（替代 location.hash 的 #g= 轨迹码）
  share(query)       { ... wx.shareAppMessage({ query }) ... },
  launchQuery()      { ... wx.getLaunchOptionsSync().query ... },

  // 剪贴板（3 处 navigator.clipboard）
  copy(text)         { ... wx.setClipboardData ... },

  // 画布
  createCanvas()     { ... wx.createCanvas() ... },

  // 生命周期
  onShow(cb) / onHide(cb)
};
```

**建议顺序**（从最容易、收益最大开始）：

1. **存储层**（60 处）—— 机械替换，最容易，先做找手感
2. **系统信息层**（约 10 处）—— 简单
3. **输入层**（95 处）—— 中等，注意 7.6 的 touchcancel 逻辑要在微信的
   `onTouchCancel` 上重新验一遍（微信的事件模型和浏览器不完全一样）
4. **音频层**（4 处 + BGM 压缩）—— 简单但体积敏感
5. **分享层**（`#g=` 改 query）—— 你的核心玩法，要认真测
6. **UI 层**（164 处）—— 最后做，工作量最大

### 6.2 第二步：UI 重写为 canvas

12 个面板要重画。按复杂度排：

| 面板 | 复杂度 | 说明 |
|---|---|---|
| `menu` 主菜单 | 中 | 标题 + 按钮列表 |
| `cards` 选卡 | **高** | 3 张卡 + 实时读数 + 协同块 + 稀有度，信息密度最高 |
| `hulls` 机库 | **高** | 船体卡 + 模块条 + 协同 + 6.3/6.4 配置行 |
| `pause` 暂停 | 中 | 统计 + 模块 chips + 协同（你刚修的 7.6c 那块） |
| `over` 结算 | **高** | 死因块 + 统计 + 分享卡 |
| `logbook` 航行日志 | **高** | ⚠️ **含两张星图（成就树 / 解锁树），有缩放引擎** —— 最费工的一块 |
| `settings` 设置 | 中 | 画质 4 档 + 特效开关 + 色盲 + 键位（**键位在小游戏里要砍掉**） |
| `board` 排行榜 | 低 | 列表 |
| `seedpanel` 种子 | 低 | 输入框（小游戏要用 `wx.showModal` 带 input 或自己画） |
| `sharecard` 分享卡 | 中 | 生成图片，小游戏里用 `canvas.toTempFilePath` |
| `victory` 通关 | 低 | — |
| `saves` 存档 | 低 | 列表 |

**省力的做法**：
- 先做一个**极简 canvas UI 框架**：按钮（命中矩形 + 按下态）、文本（字号/对齐）、
  面板（背景 + 边框 + 标题）。这三层能覆盖 80% 的面板。
- **不要 1:1 复刻 H5 版的视觉**。小游戏屏幕小、性能弱，UI 要更粗、更大、更少字。
- 星图（logbook）如果太费工，**先砍掉或降级成列表**，
  等主体跑通再补 —— 它是加分项，不是上架必需。

### 6.3 第三步：音频处理

```bash
# 9 首 BGM 统一转 64k 单声道（ffmpeg）
ffmpeg -i input.mp3 -ac 1 -b:a 64k output.mp3
```

- 转完约 16 MB → 放进**分包**，按需加载
- 音效（如果有的话）转同样格式，主包能放下就放主包（秒开体验好）
- ⚠️ 小游戏音频有**并发数限制**，同时播的音效别太多

> 所以我才建议 **C（H5 换渠道）先做** —— 今天就能拿到玩家反馈，
> 而 A 是长线投入。

大部分小游戏做的是「消消乐 + 广告」，你做的是**有深度、可比较、可炫耀**的东西。
这在微信生态里是稀缺的。

**但深度也是双刃剑** —— 微信小游戏的主流用户要的是「30 秒上手」。
移植时建议：
- 保留深度（这是你的护城河）
- **但把上手门槛降下来** —— 首屏直接进游戏，别让玩家先读教程

这个平衡值得你花时间想。

## 10. 一句话总结

**能上，0 成本能上，个人主体能上，免版号能上。**
但**「上架」不是终点，「移植」才是主要工作量** ——
约 2500–3500 行新增、1–3 个月，外加一个 30–60 工作日的软著等待期。

**今天就能做的三件事**（按优先级）：
1. **递交软著**（最长的关键路径，先排队）
2. **H5 版推 GitHub Pages**（路线 C，今天就有玩家，还能攒推广素材）
3. **定死游戏名 + 注册小游戏账号**（名称备案后锁死，先想清楚）

**不要做的事**：买量、找代办软著、注册公司、买服务器。都不需要。
