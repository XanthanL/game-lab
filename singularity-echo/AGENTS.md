## 0. 第一约束：这是一个 11621 行的单文件

`singularity-echo/index.html` 里装着全部 CSS（1094 行）、全部 HTML、全部 JS（52 个分节）。
**单文件是刻意的设计主张**（项目 README 的主线就是"一个 HTML 文件能走多远"），
不要提议拆成多文件——那是产品决策，不是技术优化。

后果只有一个，但很致命：**所有写 `index.html` 的会话都在改同一个文件**。
所以分工的第一刀不是"关注点"，而是**"你写不写 index.html"**。

| 角色 | 写 index.html 吗 | 冲突风险 |
|---|---|---|
| A 玩法 | 写（独占玩法分节） | 中 |
| B 表现 / UI | 写（独占表现分节 + `<style>`） | 中 |
| C 系统 / 平台 | 写（独占系统分节） | 中 |
| D 内容 / 叙事 | **不写** —— 只写 `lore/*.md` 与文案表 | 零 |
| E 质量 / 度量 | **不写** —— 只写 `test/probe-*.js` 与报告 | 零 |

## 4. 所有角色共用的硬约束

1. **先量后改。** 说"这里慢 / 这里不对"之前先跑探针把数字拿出来。
   本项目的每一次正确决策都是量出来的（Boss 轮换 11.58% 连撞、色盲三对 sRGB 距离、
   绘制调用 100%→63%，全是实测数字）。
2. **一步一验收。** 一个小任务做完就验，不攒批量。
3. **行号会漂，以函数名为锚点。** 提示词和文档里不要写死行号。
4. **语法先过**：改完先 `node --check`（抽内联脚本）再谈验收。
5. **视觉改动**过一遍 `impeccable`；**动效改动**用 `animate` 定参数，不凭手感写数字。
6. **token 铁律**：`--c-x` 必配 `--c-x-rgb`；改 token 名要扫 `var(--old)`；
   `:root` 是 R1/R5 唯一豁免区。收工前跑 `node audit-tokens.js`。
7. **改 `index.html` 前先备份回退点**到 `.workbuddy/backups/`（该目录不入版本控制）。
8. **禁止全局重排 / 格式化 / 批量替换。** 这会让所有人的 diff 同时冲突——
   你省了自己的事，毁了所有人的合并。
9. **提交信息写人话**：`fix(玩法): xxx` / `feat(表现): xxx`，不要写 `update`。
10. **收工前跑回归**：`singularity-echo/test/` 下 50 个 `phase*-check.js`，
    跑法见 `test/README.md`。

## 5. 沟通协议

完整协议见 **`agents/README.md`**。三条最重要的：

1. **每个会话必须在自己的 git worktree 里工作**，不许直接动 `E:\Code\game-lab`。
   五个会话共用一个工作区 = 互相踩 index 和 checkout（已经真实发生过一次：
   一个会话 staged 了文件，另一个 commit 时把它的半成品一起提交了）。
2. **不同会话之间没有消息通道，也不能互相 @。唯一共享介质是磁盘。**
   所有沟通都写成文件：角色卡（进度）、`agents/REQUESTS.md`（请求）、
   `agents/BASELINE.md`（共享数字）。
3. **请求不是实时工单。** 别人不会立刻看到。它真正的用途是——
   下一次人类合并时，你有一张清单可以照着走。

---

## 6. 合并顺序（你来做，agent 不做）

1. 每个角色一个 worktree + 一个分支：`agent/a-玩法` … `agent/e-质量`
2. **一次只合一个。** 合完立刻跑全套回归脚本，绿了再合下一个。
3. 冲突时看 §1 的所有权表判定；判不了的（比如都动了 `boot`）——
   让**后合并的那一方 rebase 到最新再重做**，不要手工缝合。
4. D / E 的分支随时可合（它们不碰 `index.html`）。
