## 现状基线（为避免拍脑袋，先列事实）

| 项 | 现状（**2026-09-10 开工前快照**，当前状态见 `DEV-PLAN.md` §0） |
|---|---|
| 天赋池 | `MODULES` 26 项 + `REPAIR`，**3 选 1**，只有 ability / stat 二分加权，无稀有度 |
| 协同 | `SYN` 12 条双天赋联动 |
| 敌人 | 20 型（`EN_UNLOCK`，1→26 波逐步解锁） |
| Boss | 6 种（`BOSS_AT`，第 5/10/15/20/25/30 波）+ 5 次精英巨像（`CHAMP_AT`）+ `AFFIX` 词缀 |
| 难度曲线 | 波次制，普通波 45s / 精英波 55s 超时强制结算，第 30 波通关后转无尽 |
| 存档 | 8 个 localStorage 键（`nova-save/slots/hulls/stats/best/lang/vol-bgm/vol-sfx`），多存档槽**已实现** |
| 元进度 | 累计统计 + 船体解锁（raven 第 15 波、nemesis 第 30 波、swarm 累计 1500 击坠） |
| 音频 | 9 首 BGM 按状态交叉淡入 + WebAudio 程序合成 SFX（含混响/闷化），BGM/SFX 分轨音量 |
| 界面 | 9 个覆盖层：menu / over / pause / cards / hulls / victory / logbook / saves / settings |
| 操作 | 键鼠硬编码 + 触屏虚拟摇杆；**无手柄** |
| 设置 | **只有 BGM / SFX 音量**，无画质档、无键位、无无障碍 |

**结论**：玩法骨架（构筑 + 波次 + Boss + 元进度）是完整的，短板在三处 ——
**① 战斗反馈层薄**（没有伤害数字，打击感只靠顿帧和相机 kick）；
**② 新手认知门槛高**（27 张卡零引导，第一局必懵）；
**③ 视觉持续加料但无规范**（多轮加特效后风格有漂移风险，bg-prototype 的教训已证明"堆元素≠质感"）。

所以路线图排成：**先修手感与认知（Phase 0–2），再扩深度与体量（Phase 3–5）**。

## 两个 skill 的分工

### 🎨 风格锚：`impeccable`（已装 v2.0.0）
管"固定风格"。它自带 `extract.md` / `normalize.md`，正好干两件事：
把现有视觉语言**提炼成设计系统**，再**规范化为可复用的 token**。
用在 Phase 0（建系统）、Phase 2（新 UI 落地）、Phase 5（收口验收）。

> 备选（若 impeccable 不够）：市场 `ui-ux-design-system`（数据驱动设计系统生成，192 条行业规则，偏网页落地页，游戏 UI 适配度待验）。

### ⚡ 动效制作：`animate`（已装，emil 系）
管"制作前端动画"。它的价值是**决策顺序**——先判断"这里该不该动"，再定时长与缓动，最后才是代码。
本项目是手写 Canvas rAF + CSS，不用 React/GSAP，所以按已定约定使用：
**只取它的 transform/opacity 优先级与 reduced-motion 原则，按目标栈（Canvas/CSS）实现，不套 React 代码。**
用在 Phase 0（定动效时长表）、Phase 1（打击感参数）、Phase 2（引导与卡牌过渡）。

> 备选：`gsap-animation-assistant`（已装）—— 专精 GSAP，本项目 DOM 动效量不足以引入 GSAP，暂不用。
> 市场 `zxh-motion-advanced` 是 React/Next 专用，不匹配当前技术栈。

**定位已明确（2026-09-10 用户确认）**：目标是**正式独立游戏**，不是展示品 ——
这会让 Phase 3–5 的权重显著提高。
**方向已明确**：换一个**更有辨识度**的视觉方向；情绪目标是**孤独壮阔、宇宙感**。

- [x] 0.1 设计上下文 → `.impeccable.md`

- [x] 0.4 **Token 落地 · 阶段 A**：硬编码值 → token 引用，值保持现状。

      （石青·隼 / 朱砂·轻剑 / 石绿·壁垒 / 锰紫·渡鸦 / 赭石·蜂群 / 铅白·回响）；
      `BOSS_STYLE` 6 种与 `ENEMY_DEFS` 20 种收敛到矿物暖色族；
      **顺带归并**：字号 30→10 档 / 时长 26→6 档 + 2 环境档 / 缓动 5 条自造曲线→2 条 /
      z-index 归 7 档
- [x] 0.8 强制自查：`node audit-tokens.js`（**R1–R5 五条规则**：CSS 无字面色值 / 引用无悬空 /
      PAL 键有 `-rgb` 伴生 / JS 语义色白名单【实体色板动态放行】/ 字号与动效无字面量，退出码即结论）

- [x] 0.9 **配色修订 B.1**（用户看实机截图后反馈，同日完成）：① 铅白去黄 → 中性白
      ② 底色提亮近 3 倍（`#05070a` → `#0e1520`）修"画面偏暗" ③ **线色族暖纸白 → 钢蓝**
      （`--c-line` `#35597d` / `--c-cyan` `#7cb2dd`）满足"边框要蓝带科技感"。
      定稿色相分工：**钢蓝 = 结构 · 中性铅白 = 读数 · 朱砂黄铜 = 内容**，
      **冷色只出现在线性元素上，不用作大面积底色**。

**验收**：新加任何 UI 元素，都不需要发明新的色值；换方向时只改 `:root`。✅ 已达成

> 关键策略：**先 token 化（等价替换）→ 再改值换方向**。
> 阶段 A 已完成且经像素级证明零变化；阶段 B 只改了 `:root` 的**值**（token 名一个没动），
> 所以全部引用方零改动即完成整体换方向。
> 实施细节（范围边界 / 五个真实踩坑 / 值映射表 / 回退点）见 `DESIGN-SYSTEM.md` 第六、七节。

## Phase 6 · 长线留存与可分享性 ✅ 完成（6.1–6.6 全部落地 · Phase 6 收官）

Phase 0–5 已全部完成。Phase 6 的定位是**让"打完一局"产生可传播、可比较、可复跑的价值**
—— 内容量已经够了（敌型 24 / 巨像 8 / 船体 7 / 模块 29 / 协同 26），
缺的是把成绩变成"别人也能体验的那一局"。

- [x] 6.1 **自定义种子与对局复现**：布局层随机源收口（`wsample` / 精英 / 词缀 / 掉落进种子流）
      + `seedAt()` 键控重播种（编队 = f(种子,波次)，选卡 = f(种子,等级)）
      + 6 位短码 + 菜单入口 + `?seed=` 直达 + 成绩卡与榜单带码
- [x] 6.2 **难度档**：三档（巡航 / 标准 / 深渊）只改敌人三围·密度·承伤与得分系数，
      **不碰玩家输出**；深渊需历史最佳波次 ≥15；每日挑战固定标准档；难度进记录·卡片·榜单
- [x] 6.3 **自定义挑战（Modifier 组合）**：5 个 Modifier `RMODS`（蜂群/铁壁/疾风/荒芜/脆命），
      最多叠 3 个；得分加成累加不连乘，与难度档相乘；六个应用点每帧只问一次 `modNow()`；
      局内 `G.rmods` 冻结；每日挑战强制清空；机库多选 + 实时倍率文案 + 记录·榜单·卡片带标记
- [x] 6.5 **幽灵回放**：每局 10Hz 录飞行轨迹（扁平数组，满了 2:1 抽稀，三个量同步动），
      按「难度+挑战+卡池」指纹分组存本机最佳（6 组 LRU），影子按 `runT` 同时间轴并排跑
- [x] 6.6 **轨迹码**：种子 + 难度 + 挑战 + 卡池 + 前 90s 轨迹压成 ~1.8K base64url 短码塞进 `#g=`，
      别人点开同地图 + 一只你的影子陪着飞（**不需要后端、不依赖微信**）
- [x] 6.4 **工坊式卡池**：玩家可禁用最多 8 / 29 个模块；`rollChoices()` 过滤；
      局内 `G.ban` 冻结；每日挑战强制清空；机库多选 chip + 实时计数 + 满位变灰；

      禁"强卡"自然更难，不引入"禁得越多分越高"的 gaming 漏洞

**验收**：同种子 + 同推进 → 编队与选卡完全一致，且与战斗时长无关（6.1 已达成）；

挂 Modifier 让「压力的形状」也变成可选项（6.3 已达成）；
**禁用"垃圾"模块让三选卡里垃圾位少一截，构筑成功率明显上去**（6.4 已达成）。

### 微信小游戏 · 个人主体的真实边界（2026-09 查证）

| 项 | 结论 |
|---|---|
| **版号** | ✅ **个人主体免版号**（平台明确的个人开发者通道）。企业主体才绕不开版号 |
| **内购 / 虚拟支付** | ❌ **个人主体不能开通**。卖道具 / 皮肤 / 会员 / 复活一律不行 |
| **广告变现 IAA** | ✅ 激励视频 / 插屏 / Banner **个人主体可接入**（这是唯一的变现路径） |
| **软著** | ⚠️ 提审**通常需要**软件著作权登记证书（中国版权保护中心，个人可自己申，约 1 个月，加急要钱）。平台偶尔开放免软著通道，**规则在变，别把"偶尔"当常态** |
| **备案** | ⚠️ 新注册小游戏**发布前必须完成备案**（微信公众平台后台，个人备案比企业简单，几天到几周） |
| **注册** | 账号类型必须选「**小游戏**」不是「小程序」；主体选「**个人**」 |
| **类目** | 个人主体可选类目有限（休闲 / 益智等），选错会被打回 |
| **配额** | 同一身份证名下小游戏数量有上限，批量矩阵要先查配额 |

**变现路径对个人开发者就一条**：免费游戏 + 激励视频广告。
接广告的话版号监管在 2025 年后趋严（多地已把纯 IAA 纳入视野），
**纯免费不带广告**是最省心的形态 —— 先上线、先有玩家，比先想变现重要。

### 移植的硬约束（从代码量出来的，不是猜的）

`index.html` 10641 行里：

| 依赖 | 处数 | 小游戏里怎么办 |
|---|---|---|
| `localStorage` | **55** | → `wx.setStorageSync` （**PAL 一层就能吃掉全部**） |
| `window.*` | **34** | → 适配器 shim，多半能直接跑 |
| `Audio` | 4 | → `wx.createInnerAudioContext`（PAL） |
| `document.createElement` | **21** | ⚠️ 只有 `canvas` 能过，其余**全废** |
| `innerHTML` | **45** | ❌ **小游戏没有 DOM，全废** |
| `addEventListener`（DOM 上） | **91** | ❌ 全废，改 canvas 命中测试 |
| `classList` | **49** | ❌ 全废 |
| `querySelector` | **33** | ❌ 全废 |
| 含 `div/button/span` 的 HTML 行 | **320** | ❌ 全废 |

**结论**：游戏**逻辑层**（波次 / 弹道 / AI / 数值 / 种子 / 难度 / 挑战 / 工坊）几乎不用改，
**UI 层是全部工作量**。菜单 / 机库 / 设置 / 成就星图 / 排行榜 / 结算 / 分享卡 /
难度档 / 挑战条 / 工坊条 —— 这些现在全是 HTML+CSS，**在小游戏里一行都跑不了**。

三条路：
- **A. UI 全部 canvas 重写** —— 最干净、视觉最统一（星图与成绩卡本来就是 canvas 画的，
  说明已有 canvas UI 能力）。量级：约 2500–3500 行。**推荐**。
- **B. 走「小程序」而不是「小游戏」** —— 有 WXML/WXSS 能直接翻译 UI，
  但**游戏必须走小游戏类目**，个人主体拉不到，类目不符会被拒。**不可行**。
- **C. 继续做 H5，换渠道** —— itch.io / GitHub Pages / 国内 H5 平台。
  零移植成本，但拿不到微信的分享裂变。**可作为过渡**。
