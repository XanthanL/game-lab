## 现状基线（为避免拍脑袋，先列事实）

| 项 | 现状 |
|---|---|
| 天赋池 | `MODULES` 26 项 + `REPAIR`，**3 选 1**，只有 ability / stat 二分加权，无稀有度 |
| 协同 | `SYN` 12 条双天赋联动 |
| 敌人 | 20 型（`EN_UNLOCK`，1→26 波逐步解锁） |
| Boss | 6 种（`BOSS_AT`，第 5/10/15/20/25/30 波）+ 5 次精英巨像（`CHAMP_AT`）+ `AFFIX` 词缀 |
| 难度曲线 | 波次制，普通波 45s / 精英波 55s 超时强制结算，第 30 波通关后转无尽 |
| 存档 | 8 个 localStorage 键（`nova-save/slots/hulls/stats/best/lang/vol-bgm/vol-sfx`），多存档槽**已实现** |
| 元进度 | 累计统计 + 船体解锁（raven 第 15 波、nemesis 第 30 波、swarm 累计 1500 击坠） |
| 音频 | 9 首 BGM 按状态交叉淡入 + WebAudio 程序合成 SFX（含混响/闷化），BGM/SFX 分轨音量 |
| 界面 | 9 个覆盖层：menu / over / pause / cards / hulls / victory / logbook / saves / settings |
| 操作 | 键鼠硬编码 + 触屏虚拟摇杆；**无手柄** |
| 设置 | **只有 BGM / SFX 音量**，无画质档、无键位、无无障碍 |

**结论**：玩法骨架（构筑 + 波次 + Boss + 元进度）是完整的，短板在三处 ——
**① 战斗反馈层薄**（没有伤害数字，打击感只靠顿帧和相机 kick）；
**② 新手认知门槛高**（27 张卡零引导，第一局必懵）；
**③ 视觉持续加料但无规范**（多轮加特效后风格有漂移风险，bg-prototype 的教训已证明"堆元素≠质感"）。

所以路线图排成：**先修手感与认知（Phase 0–2），再扩深度与体量（Phase 3–5）**。

## 两个 skill 的分工

### 🎨 风格锚：`impeccable`（已装 v2.0.0）
管"固定风格"。它自带 `extract.md` / `normalize.md`，正好干两件事：
把现有视觉语言**提炼成设计系统**，再**规范化为可复用的 token**。
用在 Phase 0（建系统）、Phase 2（新 UI 落地）、Phase 5（收口验收）。

> 备选（若 impeccable 不够）：市场 `ui-ux-design-system`（数据驱动设计系统生成，192 条行业规则，偏网页落地页，游戏 UI 适配度待验）。

### ⚡ 动效制作：`animate`（已装，emil 系）
管"制作前端动画"。它的价值是**决策顺序**——先判断"这里该不该动"，再定时长与缓动，最后才是代码。
本项目是手写 Canvas rAF + CSS，不用 React/GSAP，所以按已定约定使用：
**只取它的 transform/opacity 优先级与 reduced-motion 原则，按目标栈（Canvas/CSS）实现，不套 React 代码。**
用在 Phase 0（定动效时长表）、Phase 1（打击感参数）、Phase 2（引导与卡牌过渡）。

> 备选：`gsap-animation-assistant`（已装）—— 专精 GSAP，本项目 DOM 动效量不足以引入 GSAP，暂不用。
> 市场 `zxh-motion-advanced` 是 React/Next 专用，不匹配当前技术栈。

## Phase 0 · 风格锚定与方向重定 ✅ 已完成

**目标**：把视觉语言从"作者的手感"变成"代码里的系统"，并把风格从"常见太空霓虹"
换成一个有辨识度的方向，之后所有新界面 / 新特效都从 token 出发。

**定位已明确（2026-09-10 用户确认）**：目标是**正式独立游戏**，不是展示品 ——
这会让 Phase 3–5 的权重显著提高。
**方向已明确**：换一个**更有辨识度**的视觉方向；情绪目标是**孤独壮阔、宇宙感**。

- [x] 0.4 **Token 落地 · 阶段 A**：硬编码值 → token 引用，值保持现状。

      （石青·隼 / 朱砂·轻剑 / 石绿·壁垒 / 锰紫·渡鸦 / 赭石·蜂群 / 铅白·回响）；
      `BOSS_STYLE` 6 种与 `ENEMY_DEFS` 20 种收敛到矿物暖色族；
      **顺带归并**：字号 30→10 档 / 时长 26→6 档 + 2 环境档 / 缓动 5 条自造曲线→2 条 /
      z-index 归 7 档
- [x] 0.8 强制自查：`node audit-tokens.js`（**R1–R5 五条规则**：CSS 无字面色值 / 引用无悬空 /
      PAL 键有 `-rgb` 伴生 / JS 语义色白名单【实体色板动态放行】/ 字号与动效无字面量，退出码即结论）

- [x] 0.9 **配色修订 B.1**（用户看实机截图后反馈，同日完成）：① 铅白去黄 → 中性白
      ② 底色提亮近 3 倍（`#05070a` → `#0e1520`）修"画面偏暗" ③ **线色族暖纸白 → 钢蓝**
      （`--c-line` `#35597d` / `--c-cyan` `#7cb2dd`）满足"边框要蓝带科技感"。
      定稿色相分工：**钢蓝 = 结构 · 中性铅白 = 读数 · 朱砂黄铜 = 内容**，
      **冷色只出现在线性元素上，不用作大面积底色**。

**验收**：新加任何 UI 元素，都不需要发明新的色值；换方向时只改 `:root`。✅ 已达成

> 关键策略：**先 token 化（等价替换）→ 再改值换方向**。
> 阶段 A 已完成且经像素级证明零变化；阶段 B 只改了 `:root` 的**值**（token 名一个没动），
> 所以全部引用方零改动即完成整体换方向。
> 实施细节（范围边界 / 五个真实踩坑 / 值映射表 / 回退点）见 `DESIGN-SYSTEM.md` 第六、七节。

## Phase 1 · 战斗反馈补完 ✅ 已完成（2026-09-10）

**目标**：让每一次开火、命中、击杀、拾取都有明确的多通道反馈。这是"手感"的 80%。

- [x] 1.1 **伤害数字** —— 新增 `dmgText(x,y,val,kind,key)` 四档（普通 / 暴击 / 弱点 / 被挡），
      在 `hurtEn` / `hurtAst` / `hurtPlayer` 三处埋点。**同目标合并累加 + 同屏上限 26 条**，
      避免连射刷屏（实测 48 次命中只出 16 条）
- [x] 1.2 **命中音效分层** —— `sfx.hit(kind)` 三档（普通 / 暴击 / 被挡）+ 击杀沿用 `boom`；

- [x] 1.4 **拾取反馈** —— 磁吸拖尾粒子（每 50ms 一点）+ 拾取瞬间白环 + 原有飘字/音效/爆发

## Phase 2 · 引导与信息传达 🔄 进行中（2.1 / 2.2 已完成，2026-09-10）

**目标**：把新手从"进游戏就懵"拉到"知道自己在干嘛"，同时给老玩家更多决策信息。

- [x] 2.1 **首局分步引导** —— 新增非模态提示条 `#guide` + `GUIDE_STEPS` 五步表：

      四条设计取舍：**非模态**（不遮罩不锁输入，提示挂在视线下方）；

      `openLevelUp` 里一行 `G.guideLvUp`，因为"看过三选一"没有别的可观测状态）；
      **全局去重**（达成过的步骤写 `nova-guide`，重开不重播，全达成后彻底沉默）；
      **允许跳跃**（某步条件先达成即记完成，不卡流程）。
      桌面 / 触屏两套按键文案，切换输入方式即时换字（`guideRefresh`）。

      **当前读数行**（`modStats(id)` 从 `moduleDetail` 的 switch 抽出，详情条与卡片共用；

- [ ] 2.3 **航行日志重构**：把 `logbook` 从"图鉴"升级为**航行日志**，一次把版式定死 ——

## Phase 3 · 构筑深度与长线留存

- [ ] 3.1 **卡牌稀有度 / 升阶**：给 `MODULES` 加 rarity 字段 + 出现权重；同一张卡重复获得可升阶（数值 + 行为变化）
- [ ] 3.2 **协同扩展**：`SYN` 12 条 → 20+ 条，优先补齐现有 26 张卡的"冷门卡"联动
- [ ] 3.3 **每日挑战**：种子化 run（固定种子 + 固定卡池 + 特殊规则），记录每日最佳
- [ ] 3.4 **成就树 · MC 式节点树**（*用户提议，放进航行日志*）：
      **节点 = 成就**（击坠数 / 最远波次 / 船体通关 / 构筑流派 / 特殊玩法），
      **连线 = 前置依赖**；未解锁 = 暗色轮廓，已解锁 = 亮起 + 连线通电，达成瞬间 = 弹窗提示。
      进度态要显示（如 `1500 击坠 · 62%`）。
      实现要点：节点坐标**写死在数据结构里**，不做自动布局；
      连线用 canvas 或 SVG 画；容器可滚动/拖拽浏览。
      数据源复用已有的 `STAT_KEY` 累计统计，**不需要新的存储键**。
      视觉上直接吃 Phase 0 的 token —— 这正好是"新 UI 不许发明新色值"的第一次真实检验。
- [ ] 3.5 **局外解锁树**：消耗累计数据解锁起始增益，让连败也有进展感

**验收**：连续 10 局不会拿到相同构筑；连败 3 局后仍有可感知的进度。

## 执行约定

1. **一步一验收**：一个小任务做完就验，不攒批量
2. **语法先过**：改完先抽内联脚本跑 `node --check`
3. **视觉改动** → 过一遍 `impeccable` 再收
4. **动效改动** → 用 `animate` 定参数，不凭手感写数字
5. **行号会漂**：以函数名为锚点，行号仅作参考
